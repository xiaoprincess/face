# 小智零件社区：网站需求与开发规范

## 1. 项目定位

本项目是一个面向电子实验、嵌入式开发和实验室器材管理的统一网站，名称为“**小智零件社区**”。它将以下功能合并到同一个账号体系和网站界面中：

1. 零件管家：管理柜子、箱号、零件型号、数量和存放位置。
2. 借用记录：用户通过网站或小智 AI 查询零件，确认后**直接登记借用记录**，不需要管理员审批。
3. 小智 AI MCP：让 ESP32 通过小智云端调用树莓派上的 MCP 服务，查询真实库存或登记借用记录。
4. 博客与协作：博客文章、评论、公告、通知和私聊。
5. 项目云盘：保存数据手册、原理图、项目资料和其他文件。
6. 树莓派硬件联动：在硬件可用时调用摄像头、人脸识别、云台和激光指示柜子。

网站应保持简洁、可靠、易于维护。库存、柜号和借用记录必须来自真实数据库，不能由模型猜测或编造。

> **重要流程约定（2026-09 变更）**：借用不再走“提交申请 → 管理员审批”的老流程，改为**用户确认后直接登记借用记录**。管理员后台只负责查看记录和管理库存，不再有“批准 / 拒绝”操作。

## 2. 技术范围

| 部分 | 技术或设备 | 作用 |
|---|---|---|
| 网站后端 | Python、Flask、Flask-SQLAlchemy | 页面、用户、库存和借用记录接口 |
| 网页前端 | Jinja2、HTML、CSS、JavaScript | 页面交互和响应式界面 |
| 数据库 | SQLite | 用户、柜子、零件、借用记录和社区数据 |
| MCP | FastMCP、stdio、WebSocket Bridge | 将本地工具连接到小智 AI |
| 小智终端 | ESP32 小智 AI 固件 | 语音询问库存和触发借用流程 |
| 树莓派 | Raspberry Pi、Nginx、Gunicorn | 运行网站、MCP 和可选硬件功能 |
| 人脸服务 | 百度 AI 人脸识别 | 注册、搜索和验证用户身份 |
| 云台模块 | 旧网站保留的 `web/agent_yuntai` 模块 | 转向人脸或目标柜子 |
| 摄像头 | Picamera2 / CSI 摄像头 | 采集人脸或视觉定位画面 |

## 3. 用户和权限

### 普通用户

- 注册、登录和退出。
- 查看自己的借用记录。
- 登记借用（选择零件、数量、用途，可上传照片）。
- 查看博客文章与公开公告。
- 发布文章、评论、发送私聊消息。
- 使用项目云盘上传和管理自己的资料。
- 通过小智 AI 查询零件库存和位置。

普通用户**不能**查看别人的借用记录，**不能**修改库存，也**不能**进入管理员后台。

### 管理员

管理员拥有普通用户的全部权限，并额外拥有：

- 查看全部借用记录（按登记时间排序）。
- 查看历史记录（老流程遗留的 pending / rejected / cancelled 记录）。
- 创建、编辑和删除柜子。
- 添加、修改和删除柜内零件。
- 修改零件数量、单位、箱号和备注。
- 查看低库存零件。
- 管理网站硬件设置和系统配置。
- 发布公告和管理需要管理员权限的社区内容。

普通用户访问管理员页面时必须返回 403 或被引导到普通用户页面，不能只依赖前端隐藏按钮来实现权限控制。

## 4. 零件库存功能

库存数据的层级关系如下：

```text
柜子
└── 零件条目
    ├── 零件名称或型号
    ├── 数量
    ├── 单位
    └── 箱号或备注
```

管理员库存页面必须具备：

- 柜子总数、零件条目数、借用记录数和低库存数量概览。
- 柜子卡片展示柜号、分类、说明和柜内所有零件。
- 按柜号、零件名称、型号、箱号或备注搜索。
- “仅低库存”筛选，默认低库存阈值为数量小于等于 5。
- 创建柜子入口始终清晰可见。
- 编辑柜子和库存的表单默认收起，避免页面过长。
- 删除柜子前必须提示；删除后历史借用记录保留，但解除柜子关联。
- 库存数量不能小于 0。
- 柜号不能重复。
- 同一个柜子可以保存多个零件条目。

登记借用时可以选择柜子，也可以由系统根据零件名称自动匹配柜子，但普通用户不能直接修改库存。

## 5. 借用记录流程

借用是**直接登记**的：用户确认零件与数量后立即生成一条“已登记”记录，没有审批环节，也没有“批准 / 拒绝 / 取消”操作。

对外呈现的记录状态只有两类：

| 对外状态 | 标签 | 含义 |
|---|---|---|
| `recorded` | 已登记 | 当前系统生成的正常借用记录 |
| `historical_pending` | 历史未完成 | 老流程遗留、当时未完成的申请 |
| `historical_rejected` | 历史未通过 | 老流程遗留、当时被拒绝的申请 |
| `historical_cancelled` | 历史已取消 | 老流程遗留、当时被取消的申请 |

正常流程：

```text
用户选择零件和数量
  → 填写用途（可选上传照片）
  → 保存即生成“已登记”借用记录
  → 管理员可在后台查看记录
```

小智语音流程：

```text
用户在小智上确认借用
  → 云台转向人脸 → 摄像头拍照 → 百度 AI 人脸验证
  → 验证通过后直接登记借用记录
  → 云台指向对应柜子
```

借用记录必须保存：借用人、零件名称、数量、用途、匹配柜子、创建时间。

### 数据库兼容说明（重要）

`part_applications` 表的 `status` 列沿用了旧约束 `pending / approved / rejected / cancelled`，数据库结构**没有改动**：

- 新登记的借用记录写入 `approved`，并通过 `PartApplication.record_status` 对外暴露为 `recorded`。
- 旧的 `pending / rejected / cancelled` 记录继续保留，只读展示为历史记录。
- 判断一条记录是否为当前正常记录时使用 `record_status == "recorded"`，不要直接比较 `status`。
- 接口返回给前端 / MCP 的 `status` 字段已经是 `recorded` 或 `historical_*`，不是数据库原始值。

**库存不做自动扣减**：登记借用只写记录，不改变 `cabinet_components.quantity`。以后如果要增加扣库存，必须单独设计防重复登记、并发超借和归还回滚的规则，不能直接在现有登记函数里随手加减。

## 6. 小智 AI 与 MCP 功能

ESP32 不直接访问 SQLite，也不直接操作网站数据库。通信路径应保持为：

```text
ESP32 小智 AI
  → 小智云端 MCP Endpoint
  → 树莓派 MCP WebSocket Bridge
  → 本地 stdio MCP Server
  → 统一网站内部 API
  → unified.db
```

当前 MCP 工具应保持以下职责：

| 工具 | 类型 | 作用 |
|---|---|---|
| `search_part` | 只读 | 按名称、型号、柜号查找库存、柜号和箱号 |
| `get_cabinet_parts` | 只读 | 查询指定柜子的全部零件 |
| `get_low_stock` | 只读 | 查询低于阈值的零件 |
| `get_inventory_overview` | 只读 | 获取柜子数量、零件条目和库存概览 |
| `request_part_borrow` | 写入 | 在用户明确借用、零件唯一且数量明确后**直接登记借用记录** |

MCP 行为规则：

1. 用户只是询问库存、型号、柜号或箱号时，只调用只读查询工具，绝不能启动摄像头或云台。
2. 用户明确说“借用、拿几个、需要刚才那个”等，并提供了唯一零件和数量后，才能调用借用工具。
3. 搜索到多个相似零件时，必须列出候选项并要求用户选择，不能自行猜测。
4. 数量没有说清楚时，必须询问数量，不能默认使用 1，也不能把库存数量当成借用数量。
5. 工具失败时必须如实说明失败原因，不能假装登记成功，也不能编造记录编号。
6. 借用工具成功后返回的记录状态是 `recorded`（已登记、无需审批）。回答时要说明零件、数量、柜号和记录编号，并说明**无需审批**、库存未自动扣减。
7. MCP 不能绕过网站权限、不能直接写 SQLite、不能修改库存。
8. MCP 与网站之间使用环境变量配置的设备令牌（`PARTS_DEVICE_TOKEN`）。令牌不能写入提示词、ESP32 固件、网页源码或 Git。
9. 使用 `request_id` 作为幂等键，防止语音重复触发产生多条记录；返回 `duplicate: true` 时说明这是已有记录的重复结果。

## 7. 树莓派硬件联动

硬件联动是可选能力，网站在普通电脑上没有摄像头、云台或百度 AI 配置时也必须能够启动。

正常借用流程：

```text
检查库存和借用参数
  → 云台转向人脸识别位置
  → 摄像头拍照
  → 百度 AI 人脸搜索
  → 验证通过后直接登记借用记录
  → 云台指向对应柜子
  → 维持激光指示时间
  → 云台恢复或结束动作
```

硬件约束：

- `web/agent_yuntai/motorDrive.py` 是已经调试完成的底层模块，禁止擅自修改。
- 网站只能把云台模块当作接口调用，并使用锁避免多个请求同时驱动云台。
- 摄像头、人脸服务或云台缺失时必须返回清楚的错误信息。
- 当前树莓派摄像头不可用时，可以启用 `PARTS_SKIP_FACE_VERIFICATION=true` 作为临时降级模式。
- 降级模式只跳过摄像头、人脸和云台动作，仍然要检查零件是否存在、库存是否足够，并正常登记借用记录，同时在结果中标注“未进行人脸识别”。
- 摄像头修复后，将该配置改回 `false`，恢复正常人脸验证流程。
- 任何硬件故障都不能导致网站主进程崩溃。

## 8. 博客、私聊、通知与云盘

网站除零件管家外，还需要保持以下协作功能：

- 博客文章、评论和回复。
- 公告：面向站点成员发布的公共信息。
- 通知：针对某个用户的借用记录、评论、提及或私聊提醒。
- 私聊：用户之间的实时消息，支持未读红点。
- 云盘：上传、查看和下载项目文件。

顶部主导航中该板块入口显示为「**博客**」，进入后的板块导航顺序与主导航保持一致：博客 → 私聊 → 通知 → 云盘（管理员额外显示「公告管理」）。

公告和通知需要在界面上区分：公告是管理员或站点发布的公共内容，通知是针对某个用户的消息提醒。

云盘文件必须遵守上传大小和文件类型限制，上传文件不能直接暴露到公共静态目录。管理员可以查看全部文件，普通用户默认只能管理自己有权限的文件。

## 9. 界面设计要求

网站当前采用用户选定的「彩色积木」风格（bento）：柔和紫、浅绿、浅蓝与桃色卡片，大圆角、清晰主按钮和适当不对称布局。登录页、用户页面与后台保持统一；当前没有外观切换入口。

通用视觉要求：

- 使用圆角卡片、柔和阴影和充足留白。
- 避免大面积方正边框和拥挤表格。
- 关键操作使用明显的主按钮。
- 不把大量内容全部堆在一个长页面中。
- 后台分为“库存管理、借用记录、新增柜子”三个页签，默认进入库存管理。
- 移动端不能出现横向滚动溢出。
- 登录页、工作台、零件管家、博客、私聊和云盘使用同一套视觉变量。
- 彩色积木样式由 `static/css/bento.css` 统一覆盖；其余仍被引用的基础样式不能直接删除。

## 10. 部署要求

### 本地 Windows

默认网站地址：

```text
http://127.0.0.1:5050
```

网站和 MCP 可以通过项目根目录的启动脚本一起运行。网站使用 Gunicorn 或 Flask 运行，MCP 使用独立进程运行。

### 树莓派

- 网站内部监听 `127.0.0.1:5050`。
- Nginx 对外提供 HTTP 端口 5000 和 HTTPS 入口。
- MCP Bridge 与网站使用同一台树莓派上的本地网络。
- 使用 systemd user service 自动启动网站和 MCP。
- 使用数据库备份后再进行迁移或结构变更。
- 部署前先检查树莓派是否在线，不在线时只提交本地变更，不强行重复连接。

### Git 规则

- 默认只在本地修改和测试。
- **没有用户明确说“上传 Git”“推送到 GitHub”或类似指令时，禁止执行 `git push`。**
- 用户明确要求上传时，先查看 `git status`，只提交本次相关文件。
- 不要提交 `.env`、密钥、数据库运行文件、日志、上传文件、虚拟环境和临时预览文件。
- 不要使用 `git reset --hard` 或覆盖用户未提交的修改。
- 所有部署修改都应有可回退的提交记录。

## 11. 安全要求

- 密码必须使用哈希保存。
- 管理员页面和写入接口必须在后端检查管理员权限。
- 百度 AI 密钥、MCP Endpoint、设备令牌和 Flask 密钥只能放在 `.env` 或服务环境变量中。
- 不在日志中记录访问令牌、完整人脸图片、密码或敏感请求参数。
- 上传文件必须检查扩展名、MIME 类型、大小和保存路径。
- 借用接口必须使用请求编号或幂等键，防止语音重复触发多条记录。
- 只读查询不能触发摄像头、云台或激光。
- 公开页面不应泄露数据库路径、内部错误堆栈或配置内容。

## 14. 开发工作顺序

处理新需求时按照以下顺序进行：

1. 先阅读相关目录、路由、模板、数据库模型和启动配置。
2. 说明当前实现、问题原因、影响范围和准备修改的文件。
3. 优先采用局部修改，不重写无关模块。
4. 涉及硬件时先检查硬件可用性，保留现有云台底层代码。
5. 修改后运行与功能相关的测试、语法检查和页面访问检查。
6. 报告修改内容、测试结果和未解决的外部条件。
7. 用户没有明确要求上传 Git 时，停留在本地，不执行推送。

- 管理员管理柜子、零件、库存和系统设置，并查看全部借用记录。

## 16. 当前已知限制

- 树莓派摄像头如果被系统识别为不可用，借用流程会使用临时免人脸验证模式（`PARTS_SKIP_FACE_VERIFICATION=true`）；这不代表人脸识别硬件已经修复。
- 数据库 `status` 列仍是旧约束，历史申请与新借用记录共存在同一张表，界面上用“已登记 / 历史记录”区分。
- 旧 ESP32 固件如果仍然写死旧 IP，需要更新地址或通过网络映射保持兼容。
- 旧版站点 `web/` 仍保留“申请 + 审批”的老实现，仅其 `agent_yuntai` 云台模块被当前网站调用；两套站点不要混用同一份数据库。
- 普通用户不能进入管理员库存管理页，这是后端权限设计，不是库存数据丢失。
- 网站端和 MCP 端必须指向同一个统一数据库，否则查询结果会出现不一致。

## 17. 本地样式与交互维护（2026-09-22）

- 固定使用「彩色积木」：紫色零件、绿色博客、蓝色私聊和桃色云盘。`bento.css` 为最终主题层，不再同时加载 `atelier.css`、`themes.css` 叠加覆盖。
- 登录、注册、工作台、库存与社区共用主题；手机云盘采用文件卡片，聊天联系人与对话上下排列。连接状态会明确显示实时连接、HTTP 同步或网络异常。
- 私聊发送期间禁止重复提交；实时连接不可用时每轮完成后间隔 5 秒同步。发送超时不会自动重发，请核对记录再决定是否重试。
- 浏览器写入需携带页面生成的 CSRF 令牌；更新网站后若旧页面提示安全验证失败，刷新页面再操作。
- 设备接口要求配置 `PARTS_DEVICE_TOKEN`，未配置时拒绝调用；旧 `/command` 接口也需要设备凭据。不要把凭据放到网页或 Git 中。
- 云盘默认限制：单文件 16 MiB、个人 256 MiB、全站 2 GiB；可通过 `.env.example` 中的 `CLOUD_*_BYTES` 设置调整。配额锁用于单进程部署，多进程部署需要共享锁或数据库级配额方案。
- 回归检查使用独立内存数据库与临时上传目录，不向正式库存、聊天或云盘写入测试数据。后端测试：`.venv\Scripts\python.exe -B -m unittest discover -s tests -q`。
